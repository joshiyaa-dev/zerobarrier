# ZeroBarrier — Voice-First Employment Platform

Voice-first job search for Tamil Nadu workers who face literacy, language, and
interface barriers. Speak in **Tamil, English, or Tanglish** ("Coimbatore la
electrician jobs irukka? salary 15000") and get ranked, explainable job matches
— spoken back aloud. Runs **100% on-device**: Web Speech API → rule-based NLU →
explainable scoring → text-to-speech. No LLM keys, no backend required.

## Features

| Area | What it does |
|---|---|
| Voice search | Tamil/English/Tanglish STT (Web Speech API), mic avatar with VAD-style states |
| Intent parsing | 30 districts ×3 scripts, 17 job categories, salary formats (15000 / 15k / 1.5 lakh), shift negation ("night shift vendam"), fresher/experience, education, employment type |
| Explainable matching | Weighted scoring: category .35 · location .25 · experience .15 · salary .15 · shift .10; hard shift-exclusion filter; per-job score breakdown bars |
| Dialogue agent | Bilingual slot-filling across turns (role → location → results); honest empty-state fallback |
| Browse mode | All listings with filters (category/district/education/salary slider/shifts), sort, pagination, search history chips |
| Job detail | Full description, skills, "why this score?" modal, share (Web Share API) |
| Saved & tracker | Bookmarks + application pipeline (Saved → Applied → Interview → Offer) |
| Profile wizard | 5-step voice/text profile stored only in localStorage; feeds daily alerts |
| Job alerts | Browser notifications for new postings matching your profile |
| Accessibility | Large-text mode, high-contrast mode, full text-input fallback |
| PWA | Installable, offline app shell via service worker |

## Data honesty

The bundled dataset (`src/data/jobs.demo.json`, 520 deterministic entries,
generated by `scripts/generate-jobs.mjs`) is a **synthetic demonstration
dataset** and is labeled as such (`source` field on every record and in API
responses). It is not real employer listings. Swap in a real feed by replacing
this file with the same schema.

## Architecture

```
Browser (all processing)
├── Web Speech API      → speech-to-text (ta-IN / en-IN)
├── src/lib/zbt/nlu.ts  → rule-based intent parser (no ML claims)
├── src/lib/zbt/search.ts → explainable weighted scorer over bundled JSON
├── src/lib/zbt/agent.ts  → dialogue state machine
└── speechSynthesis     → spoken results
Optional: local whisper/piper Python backend is auto-detected (/jobs probe).
```

## Run

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # 14 unit tests (parser/scoring/dialogue)
npm run build        # production build to dist/
node scripts/generate-jobs.mjs   # regenerate dataset deterministically
```

## Deploy (Vercel)

Import the repo → framework Vite → deploy. `vercel.json` adds a daily cron
(`/api/cron-expire`) and `/api/jobs` serves the dataset as JSON with optional
`?district=&category=&limit=` filters.

## Limitations

- Speech recognition requires Chrome/Edge (Chromium Web Speech implementation).
- Rule parser handles the documented phrasing patterns, not open-ended grammar.
- Dataset is synthetic (see above).
